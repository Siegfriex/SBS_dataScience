# 1. Executive verdict

연구의 중심 주장은 다음과 같다.

> 2023년 이후 링커리어에 게시된 AI·IT 관련 채용공고에서 신입 공고의 상대적 비중은 낮아지고 인턴 공고의 상대적 비중은 높아졌는가. 동시에 인턴에게 요구되는 필수 사전경험과 NCS 기준 담당업무 수준은 높아졌는가.

이 설계는 실행 가능하지만 다음 네 조건을 충족해야 한다.

1. `entryRate`와 `internRate`의 분모는 각 시점에 새로 게시된 전체 유효 공고의 고유 `postingId` 수로 고정한다.
2. 링커리어의 2019~2026년 과거 공고 접근 가능성과 월별 수집 완전성을 먼저 검증한다.
3. 동일 페이지의 신입·인턴·경력 혼합공고는 공고 수와 트랙 분석을 분리한다.
4. NCS 수준 매핑은 도구명이나 단어 하나가 아니라 직무 문장과 능력단위·학습모듈의 대응 근거를 보존한다.

현재 완료 판정은 `MEASUREMENT_READY`다. 과거 공고 접근성과 DOM·API 구조가 확정되면 `DATA_READY`로 승격한다.

# 3. 분석 코호트와 관측단위

## 3.1 코호트

- `coreAiIt`: 사전 등록된 NCS 코드 집합에 속하는 AI·IT 관련 직무
- `allJobs`: 링커리어에서 수집 가능한 전체 직무
- RQ1·RQ2의 주 결과는 `coreAiIt`
- RQ4만 `allJobs`

## 3.2 관측단위

- 원천 공고단위: `postingId`
- 공고 내 모집트랙단위: `trackId`
- 공고 내 섹션단위: `sectionId`
- 원자 요건단위: `requirementId`
- NCS 매칭단위: `matchId`
- 월별 집계단위: `periodMonth × cohortType × jobCode`

## 3.3 공고 수와 트랙 분석의 분리

기사에서 말하는 공고 수는 채용인원 수가 아니라 고유 공고 페이지 수다.

혼합공고는 다음과 같이 처리한다.

1. 원천 페이지는 `postingId` 하나로 유지한다.
2. 공고 안에서 신입·인턴·경력 트랙이 섹션별로 분리 가능하면 `trackId`를 여러 개 생성한다.
3. RQ1의 분모와 공고수는 항상 `distinct postingId`로 계산한다.
4. RQ2의 요건·담당업무 분석은 분리된 `trackId`를 사용한다.
5. 트랙 분리가 불가능하면 `trackType=mixedUnresolved`로 두고 RQ1의 전체 분모에는 포함하되 E0/E1·인턴 접근성·NCS 수준 분석에서는 제외한다.

따라서 혼합공고를 신입이나 인턴 중 하나로 강제 배분하지 않으며, 같은 공고를 여러 건으로 과대계산하지 않는다.

# 5. 진입 접근성 라벨

사용자 검수본의 E0~E3/U를 유지하되, 인턴이 명목 신입 분모에 혼입되는 문제를 막기 위해 일반 채용과 인턴 라벨을 분리한다.

## 5.1 일반 채용 `careerClass`

| 기사 표현 | 라벨 | 분석값 | 정의 |
|---|---|---|---|
| 개방신입 | E0 | `openEntry` | 비인턴, 신입·경력무관 표기, 요구경력 0개월, 필수 사전경험 없음 |
| 제한신입 | E1 | `restrictedEntry` | 비인턴, 신입·경력무관 표기, 양의 요구경력 또는 필수 사전경험 존재 |
| 초급경력 | E2 | `earlyCareer` | 비인턴, 신입표기 없음, 1~2년 요구경력 |
| 경력직 | E3 | `experienced` | 비인턴, 신입표기 없음, 3년 이상 또는 명시적 경력직 |
| 판정불가 | U | `unknown` | 필수·우대 경계 또는 경력조건 판정 불가 |

기호:

- \(I_j\): 인턴 공고 또는 트랙이면 1
- \(N_j\): 신입 또는 경력무관 표기이면 1
- \(R_j\): 양의 최소 요구경력이 필수이면 1
- \(P_j\): 이전 인턴·동일 직무·상용 프로젝트 등 필수 사전경험이면 1
- \(B_j\): 필수와 우대의 경계를 신뢰 가능하게 판정했으면 1
- \(Y_j\): 최소 요구경력 연수
- \(C_j\): 명시적 경력직이면 1

\[
CareerClass_j =
\begin{cases}
U,& B_j=0 \\
E0,& I_j=0,N_j=1,R_j=0,P_j=0 \\
E1,& I_j=0,N_j=1,(R_j=1 \lor P_j=1) \\
E2,& I_j=0,N_j=0,C_j=0,1\le Y_j\le 2 \\
E3,& I_j=0,N_j=0,(Y_j\ge3 \lor C_j=1) \\
U,& otherwise
\end{cases}
\]

명목 신입은 다음과 같다.

\[
N^{nominal}_{o,t}=N^{E0}_{o,t}+N^{E1}_{o,t}
\]

인턴은 명목 신입 분모에 넣지 않는다.

## 5.2 인턴 접근성 `internAccessClass`

| 기사 표현 | 라벨 | 분석값 | 정의 |
|---|---|---|---|
| 개방형 인턴 | I0 | `openIntern` | 필수 경력과 필수 사전경험이 없음 |
| 제한형 인턴 | I1 | `restrictedIntern` | 양의 필수 경력 또는 필수 사전경험이 있음 |
| 판정불가 인턴 | IU | `unknownIntern` | 필수·우대 경계 판정 불가 |

\[
RestrictedIntern_j =
I_j B_j \mathbb{1}(R_j=1 \lor P_j=1)
\]

사용자 검수본의 더 좁은 정의도 별도 지표로 보존한다.

\[
ExperiencedIntern_j=I_jP_jB_j
\]

- `restrictedInternFlag`: 경력 또는 필수 사전경험 중 하나 이상
- `experiencedInternFlag`: 이전 인턴·동일 직무·상용 프로젝트 등 필수 사전경험이 명시된 엄격한 정의
- 포트폴리오 제출만으로는 `experiencedInternFlag=1`이 되지 않는다.
- 우대조건만으로는 제한형 인턴으로 분류하지 않는다.

# 6. 진입장벽 특징

주 결과는 필수요건을 기준으로 한다. 우대요건은 원문 보존과 보조 설명을 위해 별도 필드로 저장한다.

| 필드 | 자료형 | 정의 |
|---|---|---|
| `minCareerMonths` | Int16 nullable | 필수 최소 경력 개월 |
| `requiredExperienceFlag` | UInt8 | 필수 경력 요구 |
| `requiredPriorExperienceFlag` | UInt8 | 이전 인턴·동일 직무·실서비스 프로젝트 등 필수 |
| `requiredPortfolioFlag` | UInt8 | 포트폴리오 필수 |
| `preferredPortfolioFlag` | UInt8 | 포트폴리오 우대 |
| `requiredProjectFlag` | UInt8 | 프로젝트 경험 필수 |
| `requiredCertificateFlag` | UInt8 | 국가공인 자격증 필수 |
| `requiredDegreeLevel` | String categorical nullable | `highSchool`, `bachelor`, `master`, `doctor`; 요구 없음·판정 불가는 null |
| `requiredSkillCount` | Int16 | 필수요건에서 매핑된 고유 NCS 능력단위 수 |
| `requiredToolCount` | Int16 | 필수 도구·언어·기술스택 수 |

## 6.1 국가공인 자격증

원본 자격증 문구는 `certificateNameRaw`에 보존하고, 국가공인 여부와 등급을 별도 산출한다.

`certificateClass`:

- `craftsman`
- `industrialEngineer`
- `engineer`
- `masterCraftsman`
- `professionalEngineer`
- `otherNational`
- null

정규식이 매칭되지 않거나 국가공인 여부를 확인할 수 없으면 null로 두며 임의 추정하지 않는다.

## 6.2 도구·기술스택

Python, SQL, Java 같은 도구명 자체에는 NCS 수준을 부여하지 않는다.

- “Python 능숙자”만 있으면 `requiredToolCount`에는 포함하지만 `toolNcsBand=null`
- “Python을 이용한 데이터 전처리 파이프라인 설계”처럼 과업 문맥이 있으면 해당 문장을 NCS 능력단위와 매칭한다.
- NCS 수준은 도구가 아니라 도구를 사용해 수행하는 직무 과업에 부여한다.

# 7. NCS 기준 업무수준

NCS는 직무에 필요한 지식·기술·태도와 능력단위를 제공하며 1~8수준 체계를 가진다. 본 연구는 NCS 능력단위, 학습모듈, 훈련기준을 직무수준의 유일한 기준 앵커로 사용한다.

## 7.1 원시 수준

- `ncsLevel`: 1~8 정수
- 원 수준을 삭제하지 않는다.

## 7.2 기사용 4개 범주

| NCS 원수준 | `ncsBand` |
|---:|---|
| 1~2 | `level1to2` |
| 3~4 | `level3to4` |
| 5~6 | `level5to6` |
| 7~8 | `level7to8` |

## 7.3 매핑 우선순위

1. 공고에 NCS 코드·능력단위가 직접 명시된 경우: `ncsUnitDirect`
2. 담당업무가 NCS 능력단위 수행준거와 직접 대응하는 경우: `ncsPerformanceCriteria`
3. NCS 학습모듈 또는 훈련기준의 과업과 대응하는 경우: `ncsLearningModule`
4. 동일 세분류 안에서 사전등록된 정규식·동의어 사전으로 대응: `dictionaryRule`
5. 동일 세분류 후보에 대한 문장 임베딩 매칭: `semanticMatch`
6. 근거가 부족하면 매핑하지 않음: `unmapped`

각 매칭은 다음을 보존한다.

- `ncsUnitCode`
- `ncsUnitName`
- `ncsLevel`
- `ncsBand`
- `mappingBasis`
- `matchScore`
- `matchRank`
- `evidenceText`

# 15. 시계열 메트릭

## 15.1 시점의 전체 유효 공고

\[
TotalValidPostingCount_t
=
\left|
\{canonicalPostingId:
canonicalPostedAt \in t,
validPosting=1\}
\right|
\]

- 새로 게시된 공고 흐름을 측정한다.
- 활성 중인 공고 재고가 아니다.
- 90일 내 재게시는 최초 게시월 한 번만 센다.
- 혼합공고도 고유 공고 하나로 분모에 포함한다.

## 15.2 포함 공고 비율

\[
EntryPostingRate_t =
\frac{
|\{postingId:hasEntryFlag=1\}|
}{
TotalValidPostingCount_t
}
\]

\[
InternPostingRate_t =
\frac{
|\{postingId:hasInternFlag=1\}|
}{
TotalValidPostingCount_t
}
\]

혼합공고 때문에 두 비율의 합은 1이 아닐 수 있다. 이는 오류가 아니라 다중모집 구조를 반영한다.

## 15.3 배타적 비율

- `entryOnlyRate`
- `internOnlyRate`
- `mixedRate`
- `experiencedOnlyRate`

이 네 지표로 혼합공고 변화에 대한 민감도 분석을 수행한다.

## 15.4 상대지수

\[
InternRelativeIndex_t=
\log\frac{InternPostingCount_t+0.5}{TotalValidPostingCount_t+1}
-
\log\frac{EntryPostingCount_t+0.5}{TotalValidPostingCount_t+1}
\]

기사에서는 “인턴의 신입 대비 상대적 공고 비중”으로 표현한다. 실제 인력 대체로 해석하지 않는다.

## 15.5 진입장벽 지표

\[
OpenEntryShare_t=
\frac{E0_t}{E0_t+E1_t}
\]

\[
RestrictedEntryShare_t=
\frac{E1_t}{E0_t+E1_t}
\]

\[
RestrictedInternShare_t=
\frac{I1_t}{I0_t+I1_t}
\]

\[
ExperiencedInternShare_t=
\frac{\sum ExperiencedIntern_j}{MappedInternCount_t}
\]

보조 지표:

- `requiredCareerShare`
- `requiredPriorExperienceShare`
- `portfolioRequiredShare`
- `projectRequiredShare`
- `certificateRequiredShare`
- `medianMinCareerMonths`

## 15.6 NCS 수준 지표

- `level3to4Share`
- `level5to6Share`
- `level7to8Share`
- `advancedDutyShare = level5to6Share + level7to8Share`
