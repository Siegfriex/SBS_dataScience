# 링커리어 접근 허용성 — robots.txt / 이용약관 실측 결과

- 원문: `docs/audit/robots_20260806.txt` (robots.txt 전문 보존)

## robots.txt

`https://linkareer.com/robots.txt` 확인 결과, `Disallow`는 전부 `/stem/learn/*`(자격시험 학습 콘텐츠 서비스) 하위 경로에만 걸려 있다. **`/calendar`, `/activity/*`, `/list/*`(채용·공모전 목록/상세) 경로는 전혀 차단되어 있지 않다.** `Allow: /`가 기본이며 Bingbot 전용 `Crawl-delay: 1`이 명시되어 있어 — 우리 수집기도 최소 1초 간격을 존중하는 것이 안전하다(자체 정책인 0.7~1.5초 지터보다 다소 여유있게 잡을 근거가 됨).

## 이용약관(`/terms`) — 자동수집 관련 조항 2건 확인

### 1. 크롤링/스크래핑 금지 조항 — **적용 범위가 STEM(기출문제) 서비스로 한정됨**

원문(발췌): *"정상적인 서비스 흐름을 벗어나 기술적 조작·크롤링·스크래핑 등 비정상적 방식으로 자료를 수집하는 행위"*

이 조항은 "기출콘텐츠"(시험 기출문제 콘텐츠) 저작권 보호 섹션 안에 위치하며, 문맥상 STEM 학습 콘텐츠 재배포 방지가 목적이다. **채용·공모전 공고(calendar/activity/recruit) 서비스에는 이 조항이 명시적으로 적용된다고 보기 어렵다.** 다만 문언 자체는 일반적 표현이라 100% 배제된다고 단정할 근거도 아니므로, "명시적 허용"이 아니라 **"해당 조항의 문맥상 타깃이 아님"** 정도로 판정한다.

### 2. 제16조(회원의 의무) — 자동 접속 프로그램 조항 (조건부)

원문(발췌): *"자동 접속 프로그램 등을 사용하는 등 정상적인 용법과 다른 방법으로 서비스를 이용하여 '회사'의 서버에 부하를 일으켜 '회사'의 정상적인 서비스를 방해하는 행위"*

**금지 조건이 "서버 부하 유발 + 정상 서비스 방해"에 결부되어 있다** — 자동화된 접근 자체를 전면 금지하는 조항이 아니라, 과도한 트래픽으로 서비스를 방해하는 경우를 금지하는 조건부 조항이다. 이는 흔한 이용약관 문구(anti-abuse)이며, **요청 속도를 상식적 수준(동시성 낮게, 지터 포함)으로 유지하면 이 조항 위반 소지는 낮다**고 판단.

### 판정: "명시적 허용"이 아니라 "조건부 허용(rate-limit 준수 시)"으로 정정

Agent 1의 최초 보고에서 "약관상 대규모 자동수집 허용 = 명시적허용"으로 기재된 부분은 과장이다. 정확히는:
- 채용/공모전 공고 열람 자체를 금지하는 명시적 조항 없음
- 자동화 접근은 "서버 부하·서비스 방해"를 유발하지 않는 한 조건부로 허용되는 것으로 해석 가능
- **법적 자문 없이 "완전 허용"으로 단정하지 않는다.** 대량 이력 백필(ID 열거 등) 실행 전, 이 판정을 사람이 한 번 더 확인하는 것을 권고.

## robots/약관 종합 권고

1. calendar/activity/recruit/list 경로 수집은 진행 가능
2. STEM(기출콘텐츠) 관련 경로는 애초에 수집 대상이 아니므로 무관
3. 요청 속도는 Bingbot 기준(`Crawl-delay:1`)을 참고해 초당 1건 이하로 유지 권고
4. 외부 ATS(saramin, jobkorea, incruit, 각 기업 자체 채용사이트 등)는 **절대 따라가지 않는다** — UR01(원천을 링커리어·NCS로 고정)과 이번 실측(§ EXTERNAL_ATS_COVERAGE.csv)이 정확히 일치하는 지점
